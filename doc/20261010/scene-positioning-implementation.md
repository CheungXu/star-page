# 场景定位落地（P0 / P1）

## 背景

星页已经能用一句话或一份文档生成网页，但首页只是四个灵感句子，点下去不会锁定页面类型。简历、博主主页、产品落地页、活动邀请函这四类页面，需要稳定的技能、固定的分享链接和能被投放的入口。

本次在分支 `feat/scene-positioning` 上完成这一层，不改 `main` 上正在运行的服务。

## 方案

四个场景写在 `config/scenes.json`。首页卡片和 `/s/{场景}` 落地页都读这份配置。

用户从某个场景开始生成时，后端按配置强制使用对应技能，不再让模型临场猜测。产品落地页会同时带上「强风格设计」技能。续写沿用会话上的场景和技能。

每个会话可以发布一条固定链接 `/u/{短名}`。之后再改页面，只是这条链接指向的版本变了，地址本身不变。发布时生成二维码、微信分享图和朋友圈海报。

简历支持三种风格、联系方式默认打码、打印导出。博主主页和邀请函可以上传头像、二维码或主视觉，图片由站点托管，生成页直接引用。

运营后台新增「场景」页，能看每个场景的落地、点击、生成、发布和外部访问，也能把公开页标成案例，「做同款」会把原需求带回首页。

## 上线注意

数据库迁移 `017_scenes.sql` 已在当前库执行，只增加字段和新表，旧版本代码不读这些字段也能继续跑。

线上 systemd 服务没有重启，因此正在对外的网站还是旧代码。要让这批能力生效，需要在确认分支后重启后端，并重新构建前端。

## 验证

- 场景目录、简历打码文案、分享标签、发布短名的单元测试通过。
- 新技能（博主主页、活动邀请函）能被加载。
- 分享图可以生成 PNG。
- 本地 8010/3010 上，场景列表、简历场景页标题、不存在的场景页返回 404、未知场景拒绝生成，均已核对。
- 本环境没有可用的浏览器工具，首页点击和发布按钮没有在真实浏览器里点过。

## 第二轮：首页案例与自传播（10 月 10 日下午）

首页恢复原来的输入框和「试试」入口，输入框下方改为「别人做的页面」：四张卡片直接显示已发布的真实页面，点卡片进入对应场景。

四个场景的技能补了首屏要求，资料不足时省略模块，不在页面顶部放编辑提示。每个场景用通义 Max、豆包 Pro、GLM-5.3、Kimi K3 各生成一份，挑选后作为案例：简历和博主主页用通义 Max，落地页用豆包 Pro，邀请函用 Kimi K3。

所有生成页右下角统一加了「用星页做同款」浮标，点击会带着场景和来源回到首页。已发布的页面在手机上多一个「发朋友圈」，弹出竖版海报，长按保存。工作区发布后的「发朋友圈」也改成弹窗。海报重新设计成渐变底、分行标题和二维码卡片，标题取生成页自己的标题。

测试中发现 Kimi K3 不接受 `temperature` 参数（百炼报错 400 InvalidParameter），线上选这个模型也会失败。已在模型目录里用 `"params": { "temperature": null }` 关掉它的 `temperature`，测试环境验证通过，线上需要下次重启后端才生效。

## 第三轮：交互精修与“所见即所得”重构（10 月 10 日傍晚）

用户反馈首屏场景按钮与定制表单观感生硬、割裂，根据真实体验诉求进行第三轮精细重构：

1. **废弃定制表单向导，回归自然语言与输入框复用**：
   - 彻底移除丑陋的姓名、职位单行输入框、风格药丸按钮和公开打码勾选框。
   - 点击场景或案例右上角「做同款」时，直接在原生输入框中预填高度自然、可随手修改的场景 Prompt，需用户补充的信息用「」占位（如昵称「」、一句话介绍「」）。
   - 后端增加容错引导约束：若用户未填留空直接发送，模型自动识别「」并合理省略，严禁凭空瞎编。
2. **素材上传入口场景化分解**：
   - 输入框上方按场景自适应露出轻量素材胶囊（如博主主页露出「＋ 上传头像」「＋ 上传微信二维码」；邀请函露出「＋ 上传背景图」「＋ 上传报名二维码」）。
   - 已选文件显示为 `头像 · xxx.png ×`，可一键独立移除；拖拽放入多图或多槽位时智能引导，防误填错位；严格限制单图 2MB 并支持前端预拦截。
3. **案例卡片“所见即所得”与双击点位解耦**：
   - 卡片主体采用原生 iframe 缩放实景渲染，叠加微光骨架（shimmer），加载完成平滑淡入。
   - **主体点击行为**直接满足用户本能预期：“点击卡片任意区域，在新标签页打开预览全页”。
   - **「做同款」按钮**轻量浮置于卡片右上角，点击精准激活场景、预填 Prompt 并平滑滚动聚焦到主输入框。
4. **生成页 Shadow DOM 浮标与海报弹窗**：
   - 「用星页做同款」浮标采用 `attachShadow({ mode: 'closed' })` 挂载，隔绝生成页未知的 CSS 污染；移动端自适应附带「发朋友圈」海报呼出入口。
   - 修复发布页面 `print_pdf` 在 CSP 沙箱中因缺少 `allow-modals` 导致 `window.print()` 失效的问题，同时优化 `window.open` 的 opener 处理避免弹窗误拦截。
