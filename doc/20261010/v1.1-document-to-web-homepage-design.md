# 星页 v1.1 首页升级：从“对话生成”到“文档转网页”

## 1. 项目背景与定位升级

星页（StarPage）在 v1.0 版本中确立了**“基于对话 Prompt 生成高品质 HTML 页面，并支持多模型并行对比”**的核心骨架。但在实际使用与用户洞察中发现关键痛点：
- **HTML 网页表达的信息通常高度结构化、数据详实且内容丰富**，用户很难仅凭一两句简单的 Chat 对话把业务需求和数据细节描述清楚；
- 用户的核心事实、数据表格和业务逻辑，往往已经沉淀在本地现成的 **Word（docx）、Excel（xlsx）、PDF、PPT** 等文档中；
- 产品的核心价值应转向**“帮助用户将现有文档快速升维为美观、便捷、可分享的交互式 HTML 网页”**，Prompt 则从“唯一内容源”退为“可选的排版风格与侧重调节器”。

基于此，我们将原有线上版本定名为 **v1.0**，本次围绕“上传文件为主、兼顾对话补充”的首页交互升级定名为 **v1.1**。

---

## 2. 方案探讨与演进历程

本次迭代经历了从“推倒重来”到“克制微调”、再到“像素级对齐”的渐进决策过程：

### 阶段一：三套大幅重构原型（已废弃）
- 初版设计了“渐进展开舱”、“复合指令卡”和“向导阶段流”三个 Demo；
- **评审反馈**：改动过大、破坏了 v1.0 建立起的轻盈极简与空气感，界面信息过载。

### 阶段二：五套克制微调方案
回到当前界面基底，提出 5 种克制改动方案：
1. **方案一（卡片内结构反转）**：上文档条 + 下对话框；
2. **方案二（双逻辑带咬合）**：卡片内微分割线界定；
3. **方案三（常驻大胶囊主入口）**：强化左下角按钮权重；
4. **方案四（外置分段切换器）**：Tab 隔离模式；
5. **方案五（情境驱动自适应卡片）**：首屏显性露出文档区，传文件后就地展示并点亮生成，无多余模式按钮。

### 阶段三：锁定方案五并精进
用户明确选定**方案五**的核心心智，并提出关键诉求：
1. **去模式化**：不设“纯文字 / 上传文档”切换按钮，不上传文档时随时支持直接手动敲字，体验必须自然连贯；
2. **重心调整**：文档区域高度更高、更具尊崇感；微调输入框高度更收敛；
3. **对齐与降噪**：解决卡片内垂直参考线对齐问题，剔除多余格式小方块与口号碎字，文字高度精炼；
4. **代码纯正性**：直接基于线上当前代码演进，保证侧边栏、标题、灵感 Chips、用户信息与计费卡片 100% 保持原版不动。

## 3. v1.1 最终落地设计规范

### 3.1 核心区域布局与尺寸节奏
| 区域 | 规格与形式 | 视觉角色与交互逻辑 |
| :--- | :--- | :--- |
| **文档主舱** | 高度约 74px（空态）<br>通透微蓝弱底 + 细虚线边框 | **第一视觉重心**。<br>• 居左：Attachment 品牌微图标盒 + 主文案“**上传文档，一键转为网页**” + 副文案“**支持 Word · Excel · PDF · PPT**”；<br>• 居右：优雅纯净的“**选择文件**”胶囊按钮；<br>• 支持全局与局部文件拖拽吸附；挂载后就地升格为文件药丸阵列（支持删除/继续添加）。 |
| **微调输入框** | 紧凑单行（min-height: 44px）<br>无边框大平层，随字数自适应撑高 | **次级调节入口**。<br>• 未传文件时：占位符引导用户直接打字，字一落定发送按钮立即激活；<br>• 已传文件时：占位符切换为选填微调，无需输入任何字即可一键直接将文档转为网页。 |
| **底栏工具条** | 极简通透布局 | 左侧保留原版多模型选择器（`2 个模型 ⌵`），右侧保留原版圆形发送按钮（`⬆`），原左下角小上传按钮已升格至顶部大舱，工具栏不再拥挤。 |

### 3.2 垂直基准线绝对对齐
彻底消除“框套框”的层级错位：
- 文档投放舱左右内边距与下方 Textarea 起笔线、底栏模型选择器及发送按钮**严格对齐在同一垂直参考线上**；
- 继承原版极光光晕、多层柔和投影与 `composer-flow` 呼吸边框动效，保持高端现代的 SaaS 质感。

## 4. 后续落地与排期建议

1. **测试验证**：目前完整代码已在预览环境（`http://localhost:3001/`）基于 Next.js 热重载服务稳定运行，并代理至真实后端 API 验证。
2. **主干合并**：改动完全收敛在前端两个文件：
   - `code/frontend/app/page.tsx`：更新 `renderPromptForm` 的 DOM 结构与 placeholder 联动逻辑；
   - `code/frontend/app/globals.css`：新增 `.hero-dropzone` 样式并微调 `.hero-prompt textarea` 最小高度。
3. **发布上线**：确认后合入主分支，重启前端 systemd 服务即可平滑发布上线。
