# 结果预览工具栏不遮挡页面 + 分享改版：三套方案对比（选型中）

## 背景

生成 3 个以上模型时，右侧是「大预览 + 底部缩略图」。原来的「打开 / 复制 / 发布固定链接」工具栏在鼠标移到大预览上时浮出来，正好盖住页面下半部分；用户想边看边点页面时，工具栏一直挡着。

同时还有两处体验问题：

- 「发布固定链接」说法太技术，用户看不懂。发布后还要再点一次「发朋友圈」才能看到海报，链接和海报分在两处。
- 底部缩略图一排放不下时，鼠标滚轮滚不动，要按住 Shift 才能横向滚。

本次只改前端，做了三套工具栏方案并行演示，选定后再正式合并上线。

## 三套方案（解决工具栏遮挡）

三套方案的共同点：页面上方不再浮任何按钮，操作挪到页面外面，区别在挪到哪里。

| 方案 | 端口 | 操作放在哪 | 特点 |
| --- | --- | --- | --- |
| A 浏览器顶栏 | 3011 | 大预览上方一条细栏：左边模型名，中间像浏览器的地址栏，右边分享、以此结果继续、放大 | 最直观，像在真浏览器里看网页；点地址栏就是复制链接。代价是页面少约 46px 高 |
| B 侧边控制轨 | 3012 | 大预览右侧一条竖排工具轨：上面是当前模型头像和序号，中间打开 / 复制 / 分享 / 放大 / 继续改，下面翻页 | 宽屏横向空间富余，页面高度一点不损失；切换模型时名字在左上角闪现约 1.7 秒后淡出 |
| C 胶片联动 | 3013 | 底部缩略图里，选中的那张向右展开成一张小卡，写着模型名、tokens、用时、积分和操作按钮 | 大预览里只有页面本身，最干净；操作跟着选中的版本走。代价是按钮更小，离页面更远 |

取舍建议：

- A：最好懂、最稳妥，学习成本最低。
- B：页面看得最完整，适合宽屏；竖排图标需要用户适应一下。
- C：最有设计感、最省空间，但操作入口相对隐蔽，适合「先看、再挑、再操作」的节奏。

## 分享（三套方案共用）

- 「发布固定链接」改名「分享」。不再区分固定链接和发朋友圈，点一下直接弹出分享窗口。
- 分享窗口左边是分享图（就是原来的朋友圈海报，背后铺一层和海报同色的氛围光），右边是固定链接和「复制」按钮，复制后按钮和链接框一起变绿显示「已复制」。
- 下方两个入口：「保存分享图」（发朋友圈、群聊）和「打开链接」（看看朋友看到的样子）；底部显示「别人打开过 N 次」。
- 说明文字讲清楚规则：同一个会话共用一条链接，分享哪个版本，朋友打开的就是哪个版本。再次分享另一个版本时，提示「链接没变，内容已换成这一版」。
- 手机上分享窗口改成从底部弹起，分享图在上、链接在下。
- 未登录点「复制 / 分享」仍会先引导登录（与原规则一致）。

## 滚轮滚动缩略图（三套方案共用）

- 鼠标在底部缩略图上滚滚轮，直接横向平滑滚动，不用再按 Shift；触控板横滑保持原样。滚到头后不再拦截滚轮。
- 缩略图两端在还能继续滚时会渐隐，提示后面还有；滚动条压细，鼠标移上去才加深。
- 用左右方向键或点胶片切换模型时，选中的那张会自动滚进可视区域。

## 怎么看

- 工作目录：`/root/star-page-worktrees/preview-toolbar`，分支 `ux/preview-toolbar-variants`。
- 启动与停止：`bash script/preview-toolbar-variants/serve.sh start|stop|status`。
- 三个地址（端口在服务器上，本机访问需要转发 3011-3013，或直接用服务器公网 IP 加端口）：
  - 方案 A：`http://<服务器>:3011/?demo=9`
  - 方案 B：`http://<服务器>:3012/?demo=9`
  - 方案 C：`http://<服务器>:3013/?demo=9`
- 演示模式 `?demo=9`：用 11-11 那次 9 个模型的真实会话（星尘回响等 8 个页面）还原工作区，不调后端、不扣积分，分享也是模拟的（链接为示例，二维码打不开）。`?demo=2` 看 1-2 个模型时的布局；`&live=1` 让 Kimi 停在生成中。
- 页面顶部中间有方案角标，点 A / B / C 在三个端口间切换并保留参数。
- 不加 `?demo` 时连的是线上后端，登录后可以打开自己的真实会话；此时点「分享」会真的发布固定链接。
