# 生成过程写入收敛

日期：2026-11-12。当日凌晨低峰上线。

## 为什么改

每次生成都会把模型的思考碎片段落成数据库里的一行，并且立刻提交。线上 247 个任务一共 775,022 行，其中思考行 710,291 行，占九成以上。平均每个任务约 3,138 次提交。思考本身前端已经不展示，这些提交只是在打数据库。

同一张表上还有一条和唯一约束重复的索引，每次写入都要多维护一份。

## 改成什么样

- 思考文字先在进程里攒着。一个任务的第一段马上落库，页面卡片据此切到「思考中」。之后凑满 5 秒或 8,000 字再写一行。阶段、状态、完成、失败这些节点写入前，会把还没落库的思考放进同一次提交，顺序不变。
- 页面输出过程中，每 50 个估算 token 的进度还要间隔 2 秒才写。刚开始输出的那条，以及完成时带真实用量的那条，不延迟。
- 用户把卡住的模型直接停掉时，没来得及落库的尾部思考丢掉。这段文字本来就没有地方显示。
- 删掉重复索引。唯一约束还在，按任务查事件的方式不变。
- 已经结束超过 10 分钟的任务，连续思考行合并成一行，文字按原顺序保留。还在跑的、刚结束的不动。

间隔都可以用环境变量调整：`GENERATION_REASONING_FLUSH_SECONDS`、`GENERATION_REASONING_FLUSH_CHARS`、`GENERATION_PROGRESS_FLUSH_SECONDS`。

思考行少掉的 710,057 行与合并前的预演一致。进度、状态、完成这些节点没有被删，多出来的是下面两次抽查自己写入的。

思考合并之后，老任务平均还有大约 261 行，绝大部分是输出过程中每 50 token 记一次的进度。页面回放时同一阶段只认最后一条，这些中间计数可以收掉。

磁盘上的文件从 254 MB 降到 205 MB。空出来的页已经可以复用，但没有把空间还给操作系统。那一步要 `VACUUM FULL`，会短暂锁表，这次没做。

## 上线时做了什么

1. 本地测试库：原有执行器测试加上思考合并、历史合并用例，13 项通过；不连库的执行器单测 10 项通过。
2. 线上执行迁移，删掉重复索引，重启后端。启动扫尾没有重跑或标失败任何任务（当时没有未完成任务）。
3. 用匿名身份抽查了两次短页面生成，各一个模型：
   - DeepSeek V4.1 Flash：8 秒完成，14 行事件，思考 2 行、1,213 字。费用约 0.02 元。
   - 豆包 Seed 2.1 Turbo：约 28 秒完成，19 行事件，思考 2 行。
   - 两次都是思考行写在「开始输出正文」之前。抽查期间数据库连接一共 2 条，其中 1 条是抽查查询自己。
4. 先预演再合并历史：227 个已结束任务、234 段连续思考，预计删除 710,057 行。第一次执行到一个超大任务时，一次删除的行数超过了数据库驱动的参数上限而中止；中止前已完成的任务各自提交、结果完整。脚本改成分批删除后再跑一次，处理完剩下的 113 个任务（430,925 行）。再跑预演，可合并的段数为 0。随后做了 `VACUUM ANALYZE`。

两次抽查页面只写了一行字，挂在一个新的匿名会话下，没有对外发布。

## 老任务的进度也收了

同一阶段、同一状态连在一起的进度收成最后一行。输出中的 token 计数因此从 62,421 行变成 226 行；「输出完成」仍是 208 行，并且都还带着接口返回的真实用量。思考完成、上传完成这些节点状态不同，没有并进去。刚结束不满 10 分钟的不动。收完再跑一次，可合并的段数为 0。

| | 收进度前 | 收进度后 |
| --- | ---: | ---: |
| 事件总行数 | 64,998 | 2,801 |
| 进度行 | 63,623 | 1,428 |
| 思考行 | 238 | 236 |
| 每个任务的事件（中位） | 约 277 | 12 |

表文件仍是 205 MB。空页可以复用，死元组为 0。要把空间还给操作系统，还是要另做一次会短暂锁表的 `VACUUM FULL`。

可复用的做法记在 `wiki/sse-background-job-streaming.md`：流式输出先在进程里合并再落库，历史数据只收已经结束一段时间的任务。
