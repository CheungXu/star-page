# 会话分叉自动成为新会话

## 背景

一个会话进行了多轮后，用户如果回到中间某一轮（比如 3 轮里的第 2 轮），选它的结果继续修改，原来的做法是把新结果追加成"第 4 轮"，只在气泡上标一个"基于第 2 轮"。分叉一多，时间顺序和"基于谁"混在同一条列表里，用户得自己理清哪轮接着哪轮。

另外发现一个老问题：不选基础、直接让一个新加入的模型继续时，这个模型拿不到前面任何内容，会从零生成。

## 方案（已确认）

- **分叉即新会话**：选中的基础结果如果不在当前会话的最后一轮，提交后自动生成一条新会话。新会话里，选中那一轮及之前的历史和原会话完全一致，新结果接在后面；原会话保持不变。是否分叉只看选的是哪一轮，和换不换模型无关。
- **侧边栏**：分叉出来的会话和普通会话平级显示，标题下标注"分叉自「原会话」· 第 N 轮"。
- **继承的历史**：完整显示每一轮所有模型的结果，被选中的那个高亮；继承部分下方有一条分界"以上 N 轮来自「原会话」"，可一键回到原会话。
- **只在提交时创建**：只点选、不提交，不会产生空会话。
- **底层仍是一棵树**：新会话不复制历史，只记录"从哪个会话的哪一轮、哪个结果分出来"。
- **删除**：删除原会话后，分叉会话里继承来的历史照常可看（标注来自已删除的会话）；原会话独有的轮次随之失效。
- **新标题**：分叉会话的标题按新需求生成，避免同一会话多次分叉后重名。
- **顺带修复**：新加入的模型接在最近一轮的结果上继续，不再从零生成。

- 前端：提交时自动截断历史并切到新会话；侧边栏标签、输入框提示、分界条已完成。

## 补充：每轮可自由换模型（同日追加）

- **问题**：原来会话里的输入框没有模型选择器，进入会话后只能沿用首页选的模型。
- **现在**：会话里的输入框也能选模型，每一轮发送前都可以增减、更换；打开历史会话时默认沿用最近一轮的模型。
- **接着改的规则同步调整**：不选基础结果时，所有模型都从上一轮接着改。上一轮用过的模型改自己那一版；新加入、上一轮没选、上一轮失败的模型，接上一轮第一个完成的结果。原来的规则下，上一轮没被选、这一轮又加回来的模型会跳回更早那一版，丢掉上一轮的修改，现在不会了。
- **验证**：自动测试新增"只留 C → 换回 B"的场景并通过。在隔离环境里实际操作：第 1 轮用 A，第 2 轮改选 B、C；两者都在 A 的结果上修改，并带上了完整的需求历史。
- 已与分叉功能一同上线。
