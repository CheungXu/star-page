# 训练授权、内容举报与授权折扣规划

**日期**：2026-10-15
**分支**：`feat/legal-agreement`
**状态**：已合入 `main` 并上线（2026-10-15），三份协议生效日期为 2026年10月15日。

## 一、需求与合规处理

| 需求 | 合规风险 | 处理方式 |
| --- | --- | --- |
| 公开页面加举报，记到数据库，后续审核 | 无 | 照做 |
| 每条数据记录生成时的授权状态 | 无，这是合规所需 | 照做；筛选时还要看用户的当前状态 |
| 默认授权，开关不显眼 | 不能藏到找不到（TC260 要求从主界面到关闭不超过 4 步） | 放在「账号 → 设置 → 数据与隐私」，共 3 步 |
| 老用户不重新同意，默认同意 | 沉默不构成同意（《个人信息保护法》第十四条） | 不弹窗、不拦截，只发一次性告知；协议上线前的旧数据单独标记，以后再决定怎么用 |
| 未登录用户的内容必须可以训练 | 不同意就不让用，构成捆绑授权（第十六条） | 匿名用户同样默认授权，但也给一个关闭入口 |
| 同意授权打折，不同意原价 | 价差过大会变成变相强制；必须明码标价 | 授权打九折或九五折，原价不提高，双方价格都公示 |

## 二、举报

- 浮标旁边加「举报」，点击后新开平台页 `/report?page=<页面ID>`。公开页面的 CSP 不允许页面里的脚本直接请求后端，所以要跳到平台页提交。
- 举报表单的内容：
  - 举报类型（单选）：诈骗、钓鱼、色情或赌博、侵权、其他；
  - 情况说明；
  - 联系方式（选填）。
- 新建 `page_reports` 表：

  | 类别 | 字段 |
  | --- | --- |
  | 被举报对象 | 页面 ID、固定链接 |
  | 举报内容 | 类型、说明、联系方式 |
  | 举报人信息 | IP 哈希、User-Agent、举报人用户 ID（可为空） |
  | 审核结果 | 状态（待审核 / 已下架 / 驳回）、审核人、审核时间、处理备注 |

- 同一 IP 对同一页面 24 小时内只能举报 1 次，每天总共最多举报 20 次。
- 运营后台加「举报审核」页：列表 → 预览页面 → 下架或驳回。下架后，页面和固定链接都返回 451。
- 邮箱作为备用渠道，保留在页脚和协议里。
- **已确认**：下架后访问只显示「该页面因违规已下架」，不通知页面所有者。
- **以后可以完善**：给页面所有者发通知，告诉他哪个页面被下架、原因是什么、怎么申诉（站内提示或短信）。

## 三、训练授权

### 用户状态

用户表新增以下字段：

| 字段 | 说明 |
| --- | --- |
| `allow_training` | 当前是否授权，默认 true |
| `training_updated_at` | 最近一次修改授权的时间 |
| `policy_notice_seen_at` | 老用户看到更新告知的时间 |

### 同意记录表 `user_consents`

每次勾选协议、开关授权、确认老用户告知，都追加一条记录。字段有：用户、事件类型、协议版本、授权状态、IP、User-Agent、时间。只追加，不修改。

### 每条数据记录生成时的授权状态

| 表 | 数据 | 新增字段 |
| --- | --- | --- |
| `generation_batches` | 提示词、选择的场景、上传的文件 | `training_consent` |
| `page_versions` | 生成的代码（含后续编辑出的版本） | `training_consent` |
| `page_assets` | 上传的图片和文件 | `training_consent` |
| `analytics_events` | 用户自己的操作行为 | `training_consent` |

`training_consent` 取三种值：

| 值 | 含义 |
| --- | --- |
| `granted` | 生成时已授权 |
| `denied` | 生成时未授权 |
| `legacy` | 协议上线前生成 |

访客访问记录（`page_view_events`）属于第三方行为，不标记，只做聚合统计用。

### 训练数据的筛选规则

一条数据可以用于训练，要同时满足以下条件：

1. 这条数据的 `training_consent` 是 `granted`；
2. 用户的当前 `allow_training` 是 true；
3. 用户没有被封禁，页面也没有被下架。

为什么还要看当前状态：用户撤回授权后，之前授权期间产生的数据，也不能再进入新的训练。已经训练好的模型，不要求剔除这部分数据（《个人信息保护法》第十五条）。

**举例**：用户先关闭授权，后来又打开。

- 关闭期间的数据记为 `denied`，永远不用于训练。
- 打开之后的数据记为 `granted`，可以使用。
- 如果他再次关闭，所有数据都暂停使用，直到他重新打开。

### 老用户

- 迁移时，老用户的 `allow_training` 都设为 true，旧数据统一标为 `legacy`。
- 上线后，老用户第一次访问时，页面底部弹一次轻提示，不打断操作：「我们更新了《用户服务协议》《隐私政策》：生成内容将用于改进模型，授权用户享受折扣，可在设置中关闭。」点「知道了」或继续使用，都记一条告知记录。
- 告知之后的新数据正常记为 `granted`。
- `legacy` 数据先不使用。将来如果要用，有两个办法：只抽取结构和代码，去掉文本内容；或者请律师评估后再决定。

### 匿名用户

- 匿名用户在数据库里也是一个用户，所以复用同一个字段，默认授权。
- 页脚原有的「使用即同意」后面加一句「并授权用于改进模型」，再加一个不起眼的「数据设置」链接，点开就能关闭。
- 匿名用户登录后合并到正式账号时，原有数据的授权状态保持不变；合并后，用户的当前状态以登录时勾选的为准。

### 开关位置

登录后，点侧边栏的账号 → 「设置」弹窗 → 「数据与隐私」，里面放一个开关，并说明关闭后不再享受折扣。从首页到关闭共 3 步。

## 四、授权折扣

- **规则**：每次生成，在扣积分时读取这条数据的 `training_consent`：
  - `granted`：按标准价的 90% 扣积分（**已确认九折**，可配置）；
  - `denied`：按标准价扣积分。

### 防止「授权生成拿折扣，生成完再关掉」（已确认）

**问题**：法律规定用户随时可以撤回对个人信息处理的同意，合同条款也不能排除这项权利（《个人信息保护法》第十五条）。所以「这一次生成永久算授权」的写法，对个人信息那部分无效。

**方案：按数据性质拆成两部分处理**

| 部分 | 内容 | 能否绑定在这一次生成上 | 撤回授权后 |
| --- | --- | --- | --- |
| 内容许可 | 生成代码的使用许可（著作权意义上的授权） | 能。这属于合同约定，可以「这一次生成，换这一次的折扣」，约定不可撤销 | 不受影响 |
| 匿名结构样本 | 生成完成时立刻提取：保留 HTML 结构、CSS、交互代码；正文替换成占位符，删掉图片、链接、手机号、邮箱、姓名；不保存用户 ID 和页面 ID | 能。匿名化之后就不再是个人信息，撤回不影响它 | 永久保留，可以训练，也可以对外提供 |
| 去标识化原文 | 提示词、带正文的完整页面、上传的文件 | 不能，用户撤回后就要停用 | 停止用于新的训练 |

**效果**：匿名结构样本是训练数据里价值最高、也最适合对外提供的部分。用户生成完立刻关闭授权，也拿不回这部分，薅羊毛基本没有意义。

**关键要求**：匿名样本必须在生成完成的同一个流程里提取，不能事后批量处理。如果用户撤回后才去提取，提取本身就是在用户撤回之后处理他的个人信息。

**不采用「撤回时补差价」**：

- 撤回授权要付钱，会被认为阻碍用户行使撤回权（第十五条要求提供便捷的撤回方式）；
- 退款、补扣、记账都很复杂；
- 差价只有一成，被薅的损失很小。

**其他细节**：开关的修改只对之后的生成生效；每次修改都写同意记录，频繁切换的账号可以在后台看到。

**协议需要写明**（加粗）：在授权状态下生成，就表示这一次的生成内容授予了内容许可，并享受折扣；这一次内容的匿名结构样本在生成时就已经提取，关闭授权后也不撤回；含个人信息的部分在关闭后停止使用。
- **为什么按次判断，不按账号判断**：折扣和这条数据有没有授权是一一对应的，用户中途改开关，也不会出现「先享受折扣再撤回授权」的空子。
- **价格展示**：选模型时显示「标准价 X 积分，授权价 Y 积分」，生成结果和积分流水里标注「授权优惠 -Z」。
- **免费试用和赠送积分**：匿名用户的免费次数不受影响，不开发、也不关闭（免费服务不能捆绑授权）。用赠送积分同样享受折扣。
- **记账**：确认收入按实际扣掉的积分计算；流水的说明里记下折扣率，方便对账。
- **合规边界**：
  - 不提高标准价来制造价差；
  - 价差不宜超过一成左右，差太多会被认为是变相强迫用户授权；
  - 两种价格都要公示，并写进协议。
- **协议需要修改**：用户协议 2.4 条、隐私政策 3.3 条、充值协议 1.4 条，都要写明授权折扣的规则；同时调整授权「默认开启」的表述。

## 五、开发顺序

1. 数据库迁移 `018`：新增 `user_consents`、`page_reports`、`training_samples` 三张表，以及用户字段、四张表的 `training_consent` 字段。`training_samples` 存匿名结构样本，不包含用户 ID 和页面 ID，只存内容哈希用于去重。
2. 后端：
   - 登录和匿名接入时写同意记录；
   - 生成时记录授权状态，扣费时计算折扣；
   - 授权开关接口、告知确认接口；
   - 举报接口和审核接口；
   - 页面下架后返回 451。
3. 前端：
   - 设置弹窗和开关、页脚的「数据设置」入口、老用户告知条；
   - 举报页、浮标上的举报入口；
   - 价格展示、运营后台的举报审核页。
4. 修改协议文本，在 3001 端口预览，确认后合入。

## 六、进度（2026-10-15 已上线）

已合入 `main` 并部署到生产环境：

- 三份协议（《用户服务协议》《隐私政策》《积分充值服务协议》）已上线，生效日期为 2026年10月15日。
- 授权快照：授权状态下生成的数据标为「已授权」，关闭开关后生成的数据标为「未授权」，且不再提取结构样本。
- 匿名结构样本：抽取后的样本中，姓名、职位、手机号、邮箱都已去除。
- 优惠与费用展示：前台和协议正文统一写「积分优惠」，不写死折数，方便后续直接调整折扣配置（当前配置为九折）。生成结果对用户只展示花费了多少积分和优惠了多少积分，实际金额成本只保留在后台，仅管理员可见。
- 举报：提交后入库；同一访客 24 小时内重复举报同一页面会被拦截；后台下架后页面显示「该页面因违规已下架」，恢复后可以正常访问。
- 设置弹窗、老用户告知条、举报页、运营后台「举报审核」页、价格页说明已同步上线。

后续可继续完善的地方（不影响当前运行）：
