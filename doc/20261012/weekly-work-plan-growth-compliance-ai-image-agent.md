## 一、 本周目标与核心背景

星页（StarPage）目前已全面跑通展示页基础形态、多模型并行对比、固定发布短链（`/u/{slug}`）以及「用星页做同款」的自传播浮标闭环。基于最新的中国大陆市场增长策略规划，当前核心任务从“闭门造车写页面”全面转向**“小成本低人力借力增长、筑牢安全合规护城河、提升生成视觉品质、预研多文件 Agent 架构”**。

本周聚焦四大模块推进：
1. **【P0】增长分发：落地方案 B（通告平台派单 KOC）+ 方案 C（CPS 渠道试水）**：通过 AI 工具链批量生产爆款选题与图文/视频物料，解决单人无精力手工引流的痛点，外包给通告平台博主。**进展（2026-10-16）**：物料与 SOP 已备；渠道调研完成；首批定为方案 2（5 个垂直中号一人一套），待发单执行。详见 `doc/20261016/koc-channel-and-batch-strategy.md`。
2. **【P0】法律合规：全链路用户协议与付费协议实装** — **已完成（2026-10-15）**：协议 v2、训练授权、举报下架、授权积分优惠已上线生产（生效日 2026年10月15日）。
3. **【P1】体验增强：网页生成支持联动 AI 生图（对象存储托管）**：在生成 HTML 过程中自动调用生图 API 生成场景图片，并托管至对象存储（OSS/COS），解决生成页缺图、死图的问题。
4. **【P2】技术预研：多文件 Agent 模式与代码沙盒架构深度调研**：针对单文件走向 Agentic 多文件生成，系统调研代码运行沙盒（Runtime）、持久化记录与对外分享链路，对比自建 Docker 与阿里云 FC 云沙箱的成本收益。

## 二、 详细任务拆解与实施方案

### 模块 1：【P0】增长分发——通告平台派单与 AI 物料自动化

#### 1.1 爆款文案与选题生成工具选型（找灵感）
- **竞品与工具现状调研结论**：
  - **蝉小红**：因不正当技术爬取数据已被法院判赔关停，市场上已无官方服务。
  - **千瓜数据**：商业版年费 8,980~29,800 元/年起（App 端月费高达 3,599 元），其用户协议严禁 API 封装或云服务器远程调用，且**无官方公共 MCP 插件**。在冷启动早期，**完全无需购买昂贵商业账号**。
- **推荐工具链打法（极低成本甚至零成本）**：
  - **小红书官方灵犀平台（免费）**：绑定官方企业号免费挖掘求职、简历相关的实时搜索热词与飙升需求词。
  - **轻量搜索工具/MCP 结合现有大模型**：利用现成的数据查询接口（如 DataXAPI MCP 按次计费，或直接在小红书 App 内搜索“网页简历/交互简历”抓取前 5 篇爆款封面与爆款标题）。
  - **AI 爆款逆向工程**：将爆款笔记的框架录入大模型，批量产出 20 套“痛点直击型”文案脚本（如《HR 实名建议：别再投 Word 简历了》、《5分钟把旧简历变成动态网页名片》）。

#### 1.2 批量视觉与视频物料自动化（做物料）
- **图片物料**：
  - 核心痛点设计：固定“惨痛 Word vs 惊艳星页”左右/上下双拼对比模板。
  - 接入图像 API（字节火山 Seedream / 豆包文生图 / 通义万相）自动化生成不同专业方向的背景图与氛围图，结合本地脚本或 Canva 模板批量合成 10 套图文封面。
- **视频物料**：
  - 录制 2~3 段真实手机在微信/浏览器中丝滑滑动星页交互简历的 10~15 秒高清无水印视频。
  - 使用剪映脚本或批量剪辑工具，配上动感 BGM 与大字标题动画，打包成通用视频素材库。

#### 1.3 通告平台派单执行（方案 B）
- **投放阵地**：螃蟹通告、**红通告**（非「红兔」）、通告星球等同步发单；测通后可加新榜有赚 / 千瓜；标杆用蒲公英。避开野生兼职与已下架代写代发 App。
- **首批策略（2026-10-16 确认）**：方案 2 — 约 5 个垂直中号（粉丝约 3,000～15,000），**一人一套**物料测款；测出最优后再裂变文案/配图放量。不先做「大量小号重复发同一套」。
- **招募规则（测款阶段）**：
  - 目标博主：与五套物料人设一一对应；近 10 篇互动正常、有真人痕迹。
  - 合作机制：算力包 + 约 100～200 元/篇；交付须标题/开头个人化 + 封面微裁，正文不贴 URL。
- **数据追踪与归因**：
  - 为每个博主生成独立带参链接（如 `/?scene=resume&utm_source=koc_01`）。
  - 通过星页 `/ops` 运营后台的「场景」漏斗，实时监测外部真实访问（UV/PV）与转化率，杜绝刷量造假。

#### 1.4 渠道分销尝试（方案 C）
- 梳理合作宣讲单页，尝试触达 1~2 个求职辅导社群主理人或高校社团主理人，测试“按有效注册 3~5 元/人”或“付费充值返佣 30%”的 CPS 合作意向（作为补充探索，不占用核心周期）。

### 模块 2：【P0】合规护城河——注册登录与付费协议实装 — **已完成（2026-10-15）**

根据我国现行监管政策，面向公众提供生成式人工智能服务及网页分发，必须建立完整的法律合规围栏，杜绝政策风险与灰黑产利用。协议 v2、训练授权、举报与授权优惠已上线生产；落地细节见 `doc/20261015/training-consent-report-discount-plan.md`。

#### 2.1 法律法规依据调研
1. **《中华人民共和国网络安全法》、《中华人民共和国个人信息保护法》**：
   - 用户注册需完成真实身份认证（手机号验证码认证已完成）；
   - 收集个人信息遵循“最小必要原则”，明确告知使用目的并提供退出删除通道。
2. **《生成式人工智能服务管理暂行办法》（国家网信办第15号令）**：
   - **第九条明确规定**：提供者应当与注册其服务的生成式人工智能服务使用者签订服务协议，明确双方权利义务；
   - **第十一条**：对使用者的输入信息和使用记录履行保护义务，防范非法留存与泄露；
   - **第十二条**：对生成的图片、网页等内容添加显式或隐式标识。
3. **《互联网信息服务深度合成管理规定》（国家网信办第12号令）**：
   - 明确使用者承担信息安全义务，严禁利用服务制作、发布虚假信息、诈骗钓鱼单页。
4. **《消费者权益保护法》及《网络购买商品七日无理由退货暂行办法》**：
   - 明示“积分充值属于数字化虚拟商品，交付即时生效，一经充值或消耗不适用七日无理由退货”。

#### 2.2 协议文本清单
- **《星页 StarPage 用户服务协议》**：
  - 核心条款：服务范围与账户安全、生成式 AI 特性说明（AI 输出内容的参考性、局限性与免责声明）、知识产权归属（用户输入及生成的页面归用户所有）、**严厉禁止行为（严禁用于博彩、杀猪盘、仿冒钓鱼、涉政涉黄，违者直接封禁并上报）**。
- **《星页 StarPage 隐私政策》**：
  - 核心条款：手机号与验证码处理规则、用户上传文件与 Prompt 数据的安全保护、展示页外部访问日志统计说明、用户注销账户与数据删除权利。
- **《星页 StarPage 积分充值服务协议》**：
  - 核心条款：积分计费与扣减标准、数字化虚拟商品交付说明、不支持退款说明、平台服务中断补救措施、发票开具流程。

#### 2.3 交互落地与硬拦截要求
- **注册/登录弹窗交互改造**：
  - 在手机号输入与获取验证码区域下方，增加复选框：`[ ] 我已阅读并同意《用户服务协议》与《隐私政策》`。

### 模块 3：【P1】体验增强——网页生成联动 AI 生图（对象存储托管）

当前模型生成单文件网页时，若需要插入配图，往往容易使用不可靠的外链或随机占位图（Placeholder），导致页面展示效果大打折扣。

#### 3.1 资产存储位置与存储桶配置
- **配置抽象与存储路径**：
  - 支持配置对象存储（OSS/COS）专用目录：`assets/generated-images/{date}/{uuid}.png`。
  - 兼容系统当前已有的阿里云 OSS 存储体系，预留支持腾讯云 COS 驱动接入。
  - 生成图上传后直接生成防篡改的稳定公网 CDN 访问链接，写入生成页 HTML 源码。

#### 3.2 网页生成时生图 API 接入机制
- **接口选型**：
  - 接入火山引擎 Seedream（字节豆包文生图 API）或阿里云百炼通义万相 API。
- **生成链路协同范式**：
  - 方案：**两阶段轻量注入**。
    1. 大模型在生成网页结构时，若遇到需要插图的场景（如博主头像、封面海报背景、项目配图），在代码中输出预留占位标记（如 `<img data-ai-prompt="科技感渐变极简背景" />`）；
    2. 生成引擎捕获该标记，异步触发生图 API；
    3. 图片生成完成并自动上传至 OSS/COS 后，将真实图片 URL 替换回 HTML。
  - 在场景配置中按需开启该特性，避免非必要生图增加开销。

### 模块 4：【P2】技术预研——多文件 Agent 模式与沙盒架构深度调研

当前星页基于“单文件 HTML + sandboxed iframe 客户端沙箱”，零服务器执行风险且零额外算力成本。如果后续演进为**多文件代码库（Agentic Codebase）**（例如支持生成包含 React / Vue / Tailwind 构建流的现代工程），必须引入代码隔离与执行环境。

#### 4.1 核心需求解构
一个完整的 Agent Codebase 体系必须回答四个问题：
1. **运行 Runtime**：不可信代码在哪里执行、编译并运行开发服务器（如 `npm run dev`）？
2. **存储记录（Storage）**：代码库多文件如何存储历史版本？
3. **使用与迭代（Agent Loop）**：大模型如何反复读写文件、运行测试、修复错误？
4. **对外分享（Publish）**：外部访客如何访问该项目？

#### 4.2 三大沙盒方案对比（基于阿里云现状与成本测算）

| 方案 | 技术形态 | 安全与隔离性 | 运行与算力成本（阿里云环境） | 对外分享与预览实现 | 适用结论 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **方案 1：纯端侧浏览器沙盒 (WebContainer)** | 基于 WebAssembly 在用户浏览器内部运行轻量 Node.js | **极高**（完全在用户本地浏览器隔离，绝不碰服务端） | **0 元**（服务端零算力、零常驻成本） | 仅在当前会话生效；对外分享需前置 build 为静态包上传 OSS | **轻量前端的最佳解法**。适合纯前端 React/Vue 模板生成。 |
| **方案 2：自建 ECS + Docker 容器池** | 在阿里云购买多核高配服务器，单机运行 Docker/DinD | **中低**（存在容器逃逸、网络攻击与服务器被打崩风险） | **极高**（至少需要 8C32G~16C64G ECS，月固定费用 **800~2,500 元**，并发利用率低时空耗严重） | 需自建 Traefik/Nginx 动态路由与多端口泛域名解析 | **强烈不建议自建**。运维重、安全漏洞大、固定成本高。 |
| **方案 3：阿里云 FC 云沙箱 (FC Agent Sandbox)** | 阿里云函数计算团队 2026 推出的专业沙箱，**原生兼容业界标准 E2B SDK** | **最高**（微虚机级别内核隔离，会话独占，支持暂停/唤醒） | **极低且按秒弹性计费**（空闲 0 成本，仅在 Agent 执行代码时扣费，无需买大服务器） | **自带端口映射**：通过 `get_host(port)` 可直接对外获得临时预览 HTTP 地址 | **推荐演进主线**。既有大厂安全保障，又完全符合按量计费逻辑。 |

#### 4.3 存储与分享的轻量化架构建议
- **存储方案**：不为每个用户挂载昂贵云盘。每个项目维护一个 Git-like 文件树元数据，源码打包存入 OSS。
- **对外分享方案（解耦开发态与发布态）**：
  - **开发调试态**：通过 FC 云沙箱或 WebContainer 临时预览；
  - **正式发布态**：Agent 完成任务后执行编译打包（`build`），将最终输出的静态产物（HTML/JS/CSS）同步到 OSS 静态托管，对外分发依然享受 CDN 加速，**对外访问彻底脱离沙箱，维持零边际算力成本**。

## 四、 风险提示与应对策略

1. **通告平台刷量与水号风险 / 查重限流**：
   - *应对*：测款阶段粉丝约 3,000～15,000，严筛互动与真人痕迹；一人一套物料并要求个人化微调；以 `/ops` 真实 `utm_source` 转化结算。
2. **生图接口延迟与费用超标**：
   - *应对*：限制单个网页最多生成 1~2 张关键配图，在生成 Prompt 中明确约定图片尺寸；引入生图超时降级策略（超时回退优雅占位，不卡死主 HTML 流程）。
3. **监管合规突发风险**：
   - *应对*：协议与举报入口已上线；运营后台可审核举报并下架公开页；持续关注内容安全机审补强。
