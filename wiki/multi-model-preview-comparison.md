# 多模型结果预览对比设计

当一次请求并行产出多个模型的页面结果时，预览区要让用户"快速并排对比、又能聚焦细看单个"。记录可复用的布局与交互原则。

## 复用单结果预览方案

每个对比单元仍是一个"真实浏览器视窗"：固定桌面视口（如 1200px）渲染，再按单元宽度 `scale = 单元可用宽 / 视口宽` 缩放（见 `generated-page-preview-design.md`）。关键点：缩放按"每个单元自己的舞台宽高"计算，而不是整个预览区，所以把缩放逻辑封装进独立的预览单元组件，各单元各算各的。

## 自适应网格 + 聚焦

- 1 个结果：占满。
- 2 个：并排两列。
- 3 个以上：不再硬塞网格（7 个模型时每格小到看不清），改为「大舞台 + 底部缩略条」：舞台显示当前选中的结果，缩略条上每个模型一格，带状态和"新完成"小圆点；左右方向键切换，另有全屏轮播。星页当前采用这种做法。
- 早期做法是两列网格加纵向滚动，并提供单元"聚焦"：点聚焦后只渲染该单元，顶部给"返回对比"出口。模型多时不如舞台加缩略条清楚。
- 左侧进度明细和右侧联动：点进度里的某个模型，右侧切到它；多轮时点某一轮的进度，右侧切到那一轮的结果。

## 给对比腾空间

并排对比时，半屏预览区里每个单元会很小。可在多模型时切换布局：让左侧会话栏收窄、右侧预览栏加宽（如对比模式下 `0.82fr : 1.45fr`），单结果时回到 1:1。窄屏回退为单列竖排。

## 每个单元的信息与动作

- 头部：模型标签 + 状态点/状态胶囊（思考中/创建中/已生成/失败）。
- 完成态：浏览器视窗预览 + 打开页面 + 复制链接（各结果独立可分享）+ "以此结果继续"（基于该节点续写/分支）。
- 进行态：骨架屏 + 当前状态文案；失败态：单元内显示错误，不影响其它模型单元。

## 经验

- 不同模型耗时不同：并排时各单元独立从"骨架屏 → 完成预览"切换，先完成的先展示，不要等全部完成再统一渲染。
- 每个结果都是独立可分享节点，复制/打开/继续都以"该节点的 page_url / page_id"为准，便于用户挑选、分享、分支。

## 大舞台不放浮层：操作挪到页面外

浮在预览页面上的工具栏（悬停出现）会挡住用户正在看、正在点的内容。把操作挪到页面外有几种位置，各有代价：

- **舞台顶栏**（像浏览器）：最直观，地址栏本身可以当「新标签页打开」；代价是页面少一截高度。
- **胶片焦点卡**：选中的缩略图向右展开一张小卡放信息和操作，大预览只有页面本身；代价是按钮离页面远一些。
- **聚光胶片**：选中的缩略图放大浮起，名字和操作压在放大缩略图的渐暗层上；不额外占宽度，但图标按钮的含义要靠悬停提示。
- 缩略图只用来认版本，盖住一小块（如底部「继续改」宽条）可以接受；页面本身不能盖。

## 焦点卡的排版细节

- 信息和按钮共用一套等分列：每项数据落在对应按钮正上方，天然对齐；列宽不够时宁可缩小间距，也不要让长数字挤进隔壁列。
- 数据行和按钮按列对齐后就是一张「小表」，两者间距要比标题到表的间距小（约 9px），表底边对齐缩略图底边；标题（模型名）在表上方剩余空间里竖向居中，不要死贴卡片上沿。三行等距排开会让三者互不归属。
- 标题左缩进到与第一列按钮图标同一竖线：缩进量 =（列宽 − 按钮内容宽）/ 2，按内容宽固定的值用 `calc()` 写死，而不是凭眼估一个 px。
- 卡片内外边距统一（缩略图四周与按钮离卡边同为 6px），文字列与缩略图间隔是它的两倍。大面积斜向渐变铺在宽卡上会显得左白右紫，改成很淡的上下渐变。
- 「对不对齐」用实测说话：脚本读 `getBoundingClientRect` 与文字 Range 的位置，比较缩略图顶 / 底、字形顶、按钮底的差值，逐个模型、逐种组合跑一遍。

## 胶片条与切换动效

- **滚轮横滑**：竖向滚轮直接驱动横向滚动（触控板横滑、Shift+滚轮仍交给浏览器；Ctrl+滚轮是缩放不拦）；滚到头不再 `preventDefault`。平滑滚动用 rAF 缓动追目标值，并检测「别处改了滚动位置」（拖滚动条、程序滚动）后立即让出，否则会和其它滚动来回拉扯。两端按可滚动方向做 `mask-image` 渐隐。
- **展开 / 收起同时进行**：每个缩略图的焦点卡常驻（非选中的 `width: 0` + `inert`），靠宽度过渡展开收起，左右缩略图跟着平滑移动；只挂载选中项会导致旧卡瞬间消失、新卡单独展开，很生硬。
- **滑动高亮底板**：底板绝对定位在胶片条里，每帧读选中格的实时 `offsetLeft / offsetWidth` 缓动追随（选中格自己也在做宽度过渡，所以不能用一次性计算的终点），稳定后停下；同一循环里把选中格平滑带进可视区，用户一滚动就不再抢位置。
- **大预览切换要跟手**：不要等新 iframe 的 `load` 再淡入（3D 页面要拉 CDN 库，常常一秒多）。新图层点击即 0.2s 淡入，未画出前背景透明，由下面的旧图层顶着防闪白；新页面 `load`（或超时 1.5s）后再移除旧图层。
- headless 浏览器里同时渲染多个 WebGL 页面极慢，截图拿不到动画中间帧：把过渡时长临时拉长（注入样式改 `transition-duration`），再用 `document.getAnimations()` 暂停在中途截图。
