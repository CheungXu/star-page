# 单文件生成式产品的截断续写、局部增量编辑与发布前无头渲染验证

面向以「大模型直接生成可运行单文件制品（HTML/SVG/React 单组件/微应用）」为核心的 AIGC 产品，单纯的「单轮流式调用 -> 落盘发布」在长文本、多轮微调与复杂前端交互下不可避免会碰到三类硬伤：**输出半途截断**、**小改重写全页又慢又贵还改丢细节**、**代码看似合法但浏览器打开即白屏或抛错**。

本文提炼一套无需引入重型 Agent 容器、仅靠轻量外层编排与一次性沙箱子进程即可落地的三段式通用范式。

---

## 一、输出截断的精准判定与断点续写

### 1. 流式接口读取 `finish_reason` 的坑

在 OpenAI 兼容流式协议（开启 `stream_options: {"include_usage": true}`）中：
- `choices[0].finish_reason` 通常出现在**最后一个正文 delta 分片**上；
- 紧随其后的最后一个 usage 分片里，`choices` 往往是空数组 `[]`。

如果在循环里每次用当前分片的 `choices[0].finish_reason` 覆盖变量、或者只在最后一个分片读取，就会把 `length` 覆盖回 `None`。正确做法是在流式循环中**一旦读到非空 `finish_reason` 就锁存下来**，挂在最终的 `done` 事件上。

### 2. 截断判定不要把「正常结束但漏写 `</html>`」当截断

现代浏览器对末尾缺少 `</html>` 有极强容错，而不同模型厂商对 `finish_reason` 的遵从度不一。判定应分两级：
1. **明确超长**：`finish_reason == "length"`（无论是在输出完整 HTML 还是局部编辑块），必判截断。
2. **厂商未给原因（`finish_reason is None`）**：看结构是否完整——完整 HTML 模式下缺 `</html>` 判截断；局部编辑块模式下存在未闭合的 `<<<<<<< SEARCH` / `>>>>>>> REPLACE` 判截断。
3. **正常 `stop`**：完整 HTML 即使漏写 `</html>` 也**不判截断**（避免浪费一整轮续写）；但若是在输出局部编辑块且标记半截未闭合，仍按截断或畸形处理。

### 3. 断点续写与兜底失败退款

- **怎么接**：把已产出的半截正文原样作为一条 `assistant` 消息塞进上下文，再追加一条简短 `user` 消息（「你的上一段输出在末尾被截断了，请严格从断点最后一个字符之后紧接着往下写，不要重复前面已有的任何字符，不要加代码块围栏或解释」）。
- **怎么拼（防模型从头重发叠成两页）**：去除模型偶发包裹的首尾代码围栏（`html` / `diff` 等）后，必须先看续写段开头：若模型无视「从断点续写」提示而以 `<!doctype` 或重复的 `<html` 重新输出了一整份文档，直接丢弃前半截、采用新的完整文档（否则 HTML 抽取器从第一处 `<!doctype` 取到最后一处 `</html>` 会把破损半页和完整页粘成一页）；编辑块同理，若续写段以 `<<<<<<< SEARCH` 开头，区分「重发第 1 块」与「续写后续块（换行衔接，防止 `>>>>>>> REPLACE<<<<<<< SEARCH` 粘连同行）」。只有正常断点续写才原样字符级拼合。
- **次数封顶与退款**：最多自动续写 1 次（可配）。若续写完仍然截断，**绝不要把残缺半成品当成功发布并扣费**，应当直接标失败并全额退回预冻结额度。

## 二、「二选一 SEARCH/REPLACE 局部编辑 + 整页原子回退」范式

多轮续写和自动修复轮不要强迫模型永远走 diff，也不要永远重写全页，最稳的做法是**让模型按改动幅度自主二选一，后端自动识别并带原子回退**。

### 1. 提示词的 6 条硬约束（实测 9 款主流模型一次命中率 83%～100%）

在续写轮的 `user` 消息中明确给出两种互斥方式（对 `system` 提示中「只输出完整 HTML」做显式本轮特例扩展）：

- **方式 A（局部编辑块，推荐用于改文案、调样式、增删单个模块）**：
  ```text
  <<<<<<< SEARCH
  （从上一版原文逐字复制的连续片段）
  =======
  （替换后的新片段）
  >>>>>>> REPLACE
  ```
  必须写清 6 条铁律：
  1. 三行标记 `<<<<<<< SEARCH`、`=======`、`>>>>>>> REPLACE` 必须完全一致且各自独占一行，禁止拼写变形、同行粘连或嵌套。
  2. `SEARCH` 必须从上一版原文**原封不动逐字复制**，严禁用 `...` 或 `<!-- 省略 -->` 跳过中间行。
  3. **唯一命中 1 处**：目标行若重复出现（如 `</div>` 或相似卡片），必须连带上下 2～5 行特征上下文一起复制确保唯一，同时避免把大段未改动代码塞进块内。
  4. **禁止无锚点空插入**：新增内容时，`SEARCH` 必须取插入点紧邻的一小段已有原文作锚点，在 `REPLACE` 中保留该锚点并附上新内容（`SEARCH` 绝不能为空）。
  5. 多处修改按原文从上到下顺序输出，块间不重叠。
  6. **针对推理（Thinking）模型的防空转提示**：「若启用了深度思考，请快速定位目标锚点后立即输出编辑块，不要在思考中反复默写未改动段落」（实测能显著压降推理耗时与思考 Token）。
- **方式 B（完整页面，用于整体换风格/大改版）**：直接输出从 `<!doctype html>` 到 `</html>` 的完整文档，严禁混入编辑标记。

### 2. 解析、两级匹配与「全或无」原子回退

- **输出分类（`classify_model_output`）**：先扫编辑标记意图——只要出现编辑标记（包括半截畸形冲突头），全部配对合法就是 `EDIT_BLOCKS`，否则一律判 `MALFORMED`（即使块内改到了 `<!doctype html>` 也不会误判成整页）；完全无编辑标记且含 `<!doctype` 或 `<html` 才判 `FULL_HTML`。
- **基准版本对齐（极易踩坑）**：应用编辑块的基准 HTML **必须是发给模型看的那一版原文**，绝不能拿经过后端二次清洗/注入 meta 后的版本去匹配，否则缩进或属性微差会导致大面积不命中。
- **两级唯一匹配**：
  1. 先做精确子串查找：命中 `1` 处直接替换；命中 `>1` 处立即判歧义失败（`ambiguous_exact_match`）。
  2. 精确命中 `0` 处时，退回「按行 `strip()` 忽略每行首尾空白」滑窗匹配：仅当滑窗同样**唯一命中 1 处**时才替换，化解模型偶发整体多缩进/少缩进两格的问题。
- **原子作废与整页回退**：哪怕有 5 个块对了 4 个、只有 1 个没对上，**整次编辑必须全部作废**（绝不交付半新半旧的撕裂页面），追加一条「第 N 个编辑块未能在原文唯一匹配，请改为直接输出修改后的完整 HTML」再调一轮兜底。
- **后续修正轮也要识别编辑块**：若局部编辑合并后的页面又触发了其他规范重试（如禁用某 CDN），由于对话上文刚用过 `SEARCH/REPLACE` 提示词，模型在修正轮很可能继续吐编辑块。此时不能简单清空编辑基准后走 HTML 抽取（否则会把裸 `<<<<<<< SEARCH` 标记当正文包进 `<body>` 发布），而应以刚合并出的完整 HTML 为新基准兼容应用编辑块，并拒绝纯文本或畸形标记。
- **双列持久化**：主输出列（如 `model_output_text`）必须保存**合并后的完整 HTML**（供下一轮续写直接取用），模型原始吐出的编辑块另存可空排查列（如 `model_edit_text`）。
- **按模型开关**：除全局开关外，模型目录支持单模型 `edit_mode: false`；每次引入新模型前用抽样探测脚本跑一遍真实页面矩阵再决定是否开启。

## 三、Playwright / Chromium 一次性子进程发布前沙箱自检

在清洗之后、上传对象存储之前，用真实无头浏览器跑 2～4 秒的渲染自检，能抓出静态正则永远看不出来的运行时缺陷（`SyntaxError` / `ReferenceError` / `TypeError`、沙箱 `SecurityError`、动画透明度锁死白屏、死循环卡死）。落地有 6 个关键工程细节：

### 1. 绝不给 Chromium 子进程设 `RLIMIT_AS`

在 Python 文档解析子进程中给 `RLIMIT_AS` 设 1.5GB 很好用，但**绝对不能照搬给 Chromium / V8**！
- V8 引擎（Pointer Compression / Sandbox Cage）与 PartitionAlloc 启动即通过 `mmap(..., PROT_NONE)` 预留数十 GB 虚拟地址空间（并不占物理内存 RSS）。一旦设置 `RLIMIT_AS`，Chromium 会在启动瞬间直接崩溃退出。
- **正确的内存防线**：① Chromium 启动参数传 `--js-flags=--max-old-space-size=256`、`--disable-dev-shm-usage`、`--disable-gpu`；② 父进程硬超时（如 15s）强杀进程树并用 `os.wait4` 实测 `ru_maxrss`（单次通常 ~200MB）；③ 宿主 worker 单元由 systemd cgroup `MemoryHigh=2G` / `MemoryMax=3G` 兜底。

### 2. Playwright 会脱离父进程组：用私有 `TMPDIR` 令牌清扫整棵进程树

即使父进程用 `subprocess.Popen(..., start_new_session=True)` 拉起 `child.py`，并在超时/取消时 `os.killpg(proc.pid, SIGKILL)`，**Playwright Node 驱动拉起 Chromium 时内部仍可能创建新的会话/进程组**，单纯杀 `proc.pid` 的进程组会漏掉孤儿 `chrome` 进程并塞满 `/tmp/playwright_chromiumdev_profile-*`。
- **根治方案**：每次检查创建独立临时目录 `/tmp/sp-render-ipc-<随机串>/`，把子进程的 `TMPDIR` / `TMP` / `TEMP` 全部指进去。Chromium 命令行参数会自动带上该目录路径。无论是正常退出、硬超时还是用户点击停止触发 `CancelledError`，回收时扫一遍 `/proc/<pid>/cmdline` 匹配该目录名，对命中的所有 `pgid` 和 `pid` 发送 `SIGKILL`，最后 `rmtree` 整个私有目录，做到 **0 残留进程、0 `/tmp` 泄漏**。
- 父进程等待子进程使用 `os.pidfd_open` + `loop.add_reader` 异步监听退出事件，**零线程占用、不阻塞事件循环与分布式心跳**。

### 3. 请求拦截复刻线上同款 CSP 沙箱，秒拒非白名单外链

不要用 `page.set_content()` 裸跑（那是在特权 `about:blank` 下运行，测不出沙箱报错，还会去公网拉野生慢图片拖死超时）：
- 统一导航到虚拟域名 `http://starpage.invalid/`，用 `context.route("**/*", ...)` 拦截主文档，原样返回 HTML 并注入**与线上网关一字不差的 `Content-Security-Policy` 响应头**（如 `sandbox allow-scripts; connect-src 'none'`）。这样模型一旦写了违规读 `localStorage` 或 `fetch` 的代码，检查阶段就会当场抛出与真实用户浏览器完全一致的 `SecurityError` 并附带行号交给修复轮。
- 除白名单可信 CDN（如 `cdn.jsdelivr.net`、`unpkg.com`）外，其余外部图片/字体/脚本请求在路由层直接 `route.abort()`，毫秒级失败，不占导航时间。

### 4. 防误报的首屏白屏判定（兼顾 SVG/Canvas 海报与 Fixed 幻灯片）

不能只看 `document.body.innerText.trim() === ""` 或 `document.body.offsetHeight === 0`（那会把纯 SVG/Canvas 视觉页和 `position: fixed` 全屏幻灯片全部误判成白屏；反过来又会漏掉「DOM 里有字但入场动画卡在 `opacity: 0`」的真白屏）。准确的页面内评估逻辑：
- 沿祖先链逐层检查计算样式：剔除 `display: none`、`visibility: hidden/collapse`、**祖先链累乘 `opacity < 0.02`**，以及被非视口祖先容器（`width < 2` 或 `height < 2` 且 `overflow: hidden/clip`）裁掉的节点。
- 用 `TreeWalker` + `Range.getBoundingClientRect()` 统计真正有非零几何包围盒的可见文本字符数；同时扫描尺寸 `>= 4×4` 且可见的 `svg`、`canvas`、`img`（含有效 `src`/`srcset`）、`video`。
- 记录可见内容中是否包含 `position: fixed/absolute` 脱离文档流的元素：只有当「既无可见文本也无可见图形媒体」，或「`html/body` 高度 `< 10px` 且不存在脱离文档流的可见元素」时才判 `blank_page`，并在诊断详情中区分「纯空 DOM」与「DOM 含文本但被 `opacity:0` 等样式隐藏」，让模型一修就准。

### 5. 跨境白名单 CDN 慢加载与真死循环 `hang` 的区分 + 预算分段

- **区分慢 CDN 与真卡死**：当页面引用了体积较大的白名单 CDN 模块（如 Three.js 后处理扩展）且跨境网络偶发抖动导致 `page.goto(..., wait_until="load")` 超时时，不要一刀切判 `hang`。只要当时有挂起的白名单 CDN 请求，先给 `page.evaluate()` 设一个 1.2s 短超时试探主线程：若主线程能正常返回且首屏已有可见内容，说明只是外链慢而非死循环，正常走完白屏与报错检查即可；只有主线程无响应才判 `hang`。
- **子进程内部扣除冷启动耗时**：浏览器冷启动本身受机器瞬时负载影响可能占 0.5～3 秒。子进程内的 `goto` 超时与 `settle` 等待必须按 `总超时 - 已流逝时间 - 收尾预留` 动态扣减，并在 `browser.close()` **之前**先把结果 JSON 原子落盘，避免刚跑完检查却在关闭浏览器那几百毫秒撞上父进程硬超时被误记为跳过。

### 6. 绝不挡发布 + `observe -> repair` 灰度防历史回溯打标

- **可用性底线与异常边界**：渲染检查器只是质量增强组件，绝不能成为单点故障。没装浏览器、并发队列满、冷启动超时一律返回 `skipped` 照常发布；`repair` 模式下自动修一次后若仍有问题，同样**照常发布**，仅在结果卡片温和提示「可能有显示问题」。注意自动修复轮的异常兜底**只能捕获上游模型调用与截断类异常**（保留修前页面继续发布），绝不能用裸 `except Exception` 把数据库提交异常也吞掉——否则 ORM 会话已处于待回滚状态，继续往下发布反而引发连环报错。外层失败收尾先 `rollback`，再对要继续读写的对象 `await session.refresh(obj)`：回滚会让已加载对象全部过期，SQLAlchemy 异步会话里读过期字段会直接抛 `MissingGreenlet`（`expire_on_commit=False` 也挡不住）。
- **检查期间的停止请求**：检查时页面已完整生成，停止只应中断检查（记 `skipped`），页面照常发布；否则用户在最后几秒点停止会白丢一个已生成好的页面。自动修复同理：修复中途停止或上游报错，发布修前页面。
- **修复没改善就退回原稿**：复检问题数不少于修复前时发布修前页面，避免发布一版同样坏、又偏离原稿的修复版。
- **续写拼接再补两条**：模型常先写一句“好的，下面重新输出完整页面”再重发，续写段开头不是标签时也要识别“短说明文字 + `<!doctype`”的重发；前缀是编辑块时不要把续写段开头的 `<html` 当重发，REPLACE 内容本身可能从 `<html` 写起。`finish_reason=length` 但整页恰好以 `</html>` 收尾时不必再续写。
- **三档开关防回溯污染**：设 `off` / `observe` / `repair` 三档。刚上线先开 `observe` 跑几天——后台照常跑检查并把结构化结果落库，但**在落库 JSON 中显式写入 `"mode": "observe", "expose_issue": false`**。读取历史会话详情的接口看见该标记永不下发前端警告标签。这样既能在数据库里 SQL 统计真实误报率，又保证未来切到 `repair` 时，观察期生成的老页面不会突然冒出红黄警告标。
