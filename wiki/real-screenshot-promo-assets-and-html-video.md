# 用真实界面做宣传素材：截图配图与 HTML 渲染讲解视频

适用于给自家网站做小红书配图、短视频讲解。核心原则是：AI 生图只负责氛围封面，证明产品存在的画面必须是真实截图。

## 为什么封面后必须跟真实截图

AI 生图里的手机、电脑屏幕永远是模型编的界面：灰色线框、乱码英文或者别家的 UI。读者把它当成你的产品，第一眼就会觉得假。做法是封面用 AI 图，后面 2 到 3 张放真实截图，只截不改，也不往图上加数字。

## 截图要点（Playwright + 无头 Chromium）

- 手机用 390×844@3x，桌面用 1440×900@2x，放大裁剪后仍然清晰。
- 服务器装好彩色 emoji 字体（Ubuntu：`fonts-noto-color-emoji`），否则带 emoji 的按钮会截成方块。真实用户手机上没有这个问题，截出来却像 bug。
- 页面里嵌了 iframe 预览时，屏幕外的 iframe 不跑入场动画，整页截图会出现空白卡片。截之前先把视口高度设成整页高度。
- 按坐标裁剪时，用 CSS 像素乘以 deviceScaleFactor。不要按缩小后的预览图量坐标。
- 想截生成过程，就真实跑一次：用全新的匿名身份、最便宜的默认模型，顺便量出真实耗时，文案里的“几分钟”“秒出”要以实测为准。

## 讲解视频：hyperframes

[hyperframes](https://github.com/heygen-com/hyperframes) 用 HTML、CSS 写画面，GSAP 时间线做动画，再用无头 Chrome 逐帧截图，交给 FFmpeg 编码。画面就是网页，所以真实截图可以直接拿来做推拉、滚动、并排。

合成规范里最容易踩的几处：

- 根节点写 `data-composition-id`、`data-width`、`data-height`、`data-duration`；时间线必须是 paused 状态，注册在 `window.__timelines[id]`，id 和根节点的 composition id 一致。
- 不要在同一个元素上既写 CSS `transform` 又用 GSAP 做位移或缩放。需要静态缩放就外面包一层，外层负责动画。
- 不要对 `.clip` 元素本身做 `opacity` 或 `visibility` 动画，要做在它的子元素上。
- `<audio>` 必须有 id，否则混音时会被漏掉，成片没有声音。
- 工程根目录只能有一个带 `data-composition-id` 的 html，模板文件要放进子目录。
- GSAP 下载到本地引用，渲染时不依赖网络。

配音节奏：每句单独做 TTS，测出每句时长，再把画面分段和字幕时间算出来填进模板。改一句台词只需重做这一句，画面自动对齐。

中文 TTS 的坑：网址里的 `-` 会被读成“减”。要给配音单独写一份读法（如“stars 杠 page 点 com”），字幕仍显示原文。合成后用 ASR 转一遍文字，核对中英混读。

## 低配服务器的速度参考

2 核 CPU、3GB 内存时，hyperframes 自动走低内存模式：单进程、软件 GL、截图方式取帧。

- `render`：一分钟 1080×1920、30 帧每秒的视频约 5 分钟出片，静止帧会被自动复用。
- `snapshot`：每帧都重新加载页面，约 1 分钟一帧，只抽关键时间点看。
- `check`：跑 10 分钟都没结束，可以只用 `lint` 加 `snapshot` 代替。
- 渲染前把大截图缩到实际要用的尺寸，即最大放大倍数乘以显示宽度，可以减少加载时间。
