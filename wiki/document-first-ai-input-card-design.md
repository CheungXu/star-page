# 文档优先型（Document-First）AI 生成输入卡片设计模式

许多以自然语言为核心的 AI 生成工具（如“Chat 聊天生成网页/报告/图表”），在产品深化阶段都会面临同一挑战：**用户很难仅凭简短 Prompt 描述清楚结构复杂、数据密集的内容，而真实内容其实已沉淀在用户的本地文档（Word、Excel、PDF 等）中**。

当产品核心诉求从“凭空想象生成”转型为“基于已有资产升维生成”时，上传要醒目，但书写区仍应是主视觉。本篇总结一套可复用的设计模式与避坑经验。

---

## 1. 核心设计原则

### 原则一：零切换门槛（去模式化）
- **反模式**：在输入卡片上方或内部加分段切换按钮（如 `[ 文档转网页 ]` 与 `[ 纯文字构思 ]`）。
  - *缺点*：强迫用户在行动前做分类决策，阻断了流畅的输入冲动，并割裂了两种本来可以混合的诉求。
- **正模式**：双向自适应激活。
  - **有文档时**：文档一拖入或选中，主 CTA（发送键）**立即点亮**，下方 Prompt 输入框自动切换为“选填微调”，无需打字即可一键直接将文档转为产物；
  - **无文档时**：用户直接无视上方文档区域，光标落入输入框直接敲字，只要敲了字，主 CTA 同样瞬间点亮。

### 原则二：消除“框套框”，统一垂直参考线
- **反模式**：在白色卡片内生硬套入一个带灰底、带内边距的次级虚线框。
  - *缺点*：出现“外边框 - 内边框 - 输入文字起笔线 - 底部按钮”多级错位，界面显得琐碎、廉价。
- **正模式**：
  - 顶部文档舱的左右边界，与中段 Textarea 的文字起笔线、底栏的工具按钮，**严格对齐在同一垂直参考线上**；
  - 采用半透明浅蓝弱底（如 `linear-gradient`）代替突兀灰底，与卡片外框的弥散流光融为一体。

### 原则三：信息层级极致降噪
- **反模式**：把格式列表（Word/Excel/PDF/PPT）、文件体积限制（50MB）、数量上限（最多3个）、操作引导（点击或拖入）、推荐标签（核心推荐）全部堆叠在界面上。
- **正模式**：
  - **主动作（1 级）**：清晰动宾短语，如“`上传文档，一键转为网页`”（10~12 字以内）；
  - **副信息（2 级）**：仅保留核心格式信息，如“`支持 Word · Excel · PDF · PPT`”；
  - **技术细节（3 级）**：单文件大小、数量上限、具体扩展名等次要约束，收敛到原生 `title`（Tooltip）或错误校验提示中，避免污染首屏空间。

## 2. 结构范式与尺寸比例

```text
┌────────────────────────────────────────────────────────┐
│  .prompt-card (外轮廓 760px，radius-xl，流动微光边框)   │
│                                                        │
│  ┌──────────────────────────────────────────────────┐  │
│  │ 1. 文档条 (高度约 64px，细虚线 + 通透浅蓝底)       │  │
│  │    [📎 图标] 上传文档，一键转为网页     [选择文件]  │  │
│  │              支持 Word · Excel · PDF · PPT       │  │
│  └──────────────────────────────────────────────────┘  │
│                                                        │
│  ┌──────────────────────────────────────────────────┐  │
│  │ 2. 主输入框 (空态 min-height: 74px，自适应撑高)    │  │
│  │    说说你想做的页面，或直接上传上方文档...        │  │
│  └──────────────────────────────────────────────────┘  │
│                                                        │
│  ┌──────────────────────────────────────────────────┐  │
│  │ 3. 底栏工具条 (高度 36px)                         │  │
│  │    [ 2 个模型 ⌵ ]                         [ ⬆ ]   │  │
│  └──────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────┘
```

### 比例协调关键点
1. **书写区只略高于上传条**：空态输入框约 74px，上传条约 64px，高度差大约 10px。输入框仍是主视觉，上传是副视觉，两者几乎齐平。
2. **上传仍然被强调**：高度让给输入框之后，强调靠浅蓝底、虚线框、图标和「选择文件」药丸，而不是再把上传条做高。
3. **输入增多时再撑高**：空态保持上述比例；文字超出后由脚本把输入框平滑撑高，上限约 180px。
4. **主 CTA 位置常驻**：发送按钮永远保持在右下角，状态由 `Boolean(hasFiles || hasText)` 统一驱动，符合用户最终注视点的心理预期。
5. **有色块比空白更重**：同样一像素，浅蓝虚线框、图标和药丸按钮比透明输入框显眼。输入框拉到 82px、比上传条高出约 18px 时，空白会被看成差距过大；收到 74px、实高只高出约 8px 才合适。「输入为主」靠略高一档，不靠把输入框做成大块空白。
