# 分享卡片：可改标题的分享浮层 + 前后端同版式海报

生成类产品（网页、海报、作品集）里「分享」的通用做法：一个按钮完成发布 + 分享，用户能改分享卡片上的字，改完所见即所得，转发出去的链接卡片和图片也跟着变。

## 交互

- **一个「分享」按钮**：不要拆成「发布固定链接」和「发朋友圈」两步。点一下即发布（幂等：同一会话一条链接，重复点只切换内容版本），浮层同时给出分享图和链接。
- **贴着按钮弹浮层，不盖全屏遮罩**：下方放得下就朝下，否则朝上；水平居中对齐按钮并夹在视口内，箭头对准按钮。浮层用 portal 挂到 `body`，否则会被横向滚动容器（胶片条）裁掉。
- **收起时机**：点浮层外、Esc、再点一次按钮；点进 iframe 预览时外层收不到点击，用「窗口失焦 + `document.activeElement` 是 IFRAME」判断。
- **布局**：分享图铺满一整列（够大才看得清、手机上能长按保存），另一列是标题 / 副标题输入框、对齐切换和操作。链接文本不用展示，「复制链接」一个按钮即可。
- **按钮顺序有含义**：和图片相关的「保存图片」放在最靠近图片的位置；对齐切换按方向排列（左对齐在左、居中在中、右对齐在右），默认居中。
- **少写说明文字**：规则类句子（「同一会话共用一条链接」）放进文档；浮层里只在需要时出现短提示，例如「链接没变，内容已换成这一版」、「别人打开过 N 次」。

## 数据与保存

- 存「用户改写值」和「生效值」两套：`custom_title` / `custom_subtitle` / `card_align` 为空表示用默认；`title` / `og_description` 存生效值，供公开页 meta 和分享图直接使用。默认标题取生成页 `<title>`（`page.title` 常是一整句需求，不适合当标题），默认副标题取场景标语或品牌句。
- 重新发布另一个版本时**保留**用户改写值；「恢复默认」= 把改写值置空，按当前版本重算默认。
- PATCH 只改请求里出现的字段（Pydantic 用 `model_fields_set` 区分「没传」和「传了 null」），`null` / 空串 = 恢复默认。
- 前端：输入时先本地重画分享图，停手约 0.7 秒再保存；关闭浮层时用 `fetch(..., { keepalive: true })` 补存。复制链接时并行触发保存，不要等保存完再复制（会丢掉剪贴板需要的用户手势）。
- 输入框被清空时，本地预览先按默认值画，服务端也恢复默认，两边一致。

## 前后端同一版式

- 实时预览必须在浏览器里画（canvas），公开页「发朋友圈」和链接卡片的图必须在服务端画（Pillow）。两处按同一套坐标写：前端 720×1080、后端 1080×1620，所有尺寸乘 1.5。改版式时两边一起改，并各出一张对照图检查。
- 前端保存图片直接导出 canvas（`toDataURL`），并把 `<img src=dataURL>` 作为预览，手机上长按即可保存。二维码图要同源加载，否则 canvas 被污染无法导出。
- Pillow 用 Noto CJK 的 `.ttc` 时要指定 `index=2`（简体中文字形），默认 `index=0` 是日文字形，部分汉字写法不同；标题用 Bold 字体。文字对齐用 `anchor="la" / "ma" / "ra"`。
- 二维码卡放在「文字下沿」与「底部落款」之间的正中（标题一到三行都匀称），不要写死 y 坐标。

## 链接卡片

- `og:title` / `og:description` / `og:image` 用生效值。用户自定义了标题时，公开页连 `<title>` 一起替换：微信里直接转发链接（不走 JS-SDK）时读的往往是 `<title>`。
- 分享图接口带短缓存（如 `max-age=300`），改完后几分钟内旧图可能仍被缓存，属正常现象。

## 埋点

打开分享、复制链接、保存分享图各一个事件，带界面方案编号（AB 分组）和模型，便于比较不同方案的传播转化。
