# 生成类产品的场景化增长与落地框架

适用于「具备通用生成能力，但在增长和商业化时必须依靠垂直高频场景切入」的 AI / AIGC / 工具类产品。通用输入留给高阶自由探索，转化与传播动作落到垂直场景。

---

## 一、 场景定义：配置驱动，拒绝硬编码

场景不是写死在前端的代码页面，而是一套中立的数据契约：

```json
{
  "key": "resume",
  "name": "网页简历",
  "emoji": "👤",
  "skill_key": "resume",
  "extra_skill_keys": ["ui-polish"],
  "tagline": "把旧简历变成 HR 愿意点开的交互网页",
  "prompt_template": "帮我把上传的简历做成一份网页简历：大厂极简风格，第一屏突出姓名、目标职位和三项最亮眼的成绩，电话和邮箱默认打码。",
  "image_slots": [],
  "features": ["print_pdf", "stable_link", "view_count"]
}
```

- **统一单一数据源（Single Source of Truth）**：首页卡片、独立投放落地页（`/s/{scene}`）、运营后台漏斗均由后端同一份配置文件或接口读取。
- **确定性技能强锁定**：对于开放式输入，可由意图路由模型猜测技能；但当用户从具体场景进入时，必须**强制注入专属制作指南（System Prompt）**，跳过意图猜测，避免生成失真。
- **续写链路继承**：在多轮对话与生成树中，子节点必须沿着会话与父链稳定继承首轮选定的 `scene_key` 与专属技能，严禁中途意外变轨。

---

## 二、 交互范式：拒绝表单化，坚持 Prompt 阈值预填

很多团队在做场景化时，容易走入“填空题向导/定制复杂表单”的误区，将大模型工具退化成了生硬难看的表单收集器。最佳的交互范式应遵循：

1. **复用原生输入框，自然语言阈值预填**：
   - 用户选择场景或点击“做同款”时，直接在主输入框内填入一段成熟、专业的默认需求模板。
   - 需要用户微调的关键字段用中文方括号「」留空（例如 `昵称「」，一句话介绍「」`）。
   - **后端容错兜底**：提示词层明确约定“若需求中包含未填写的「」，代表用户未提供该信息，应当合理省略或泛化，严禁凭空编造事实”。
2. **素材上传入口按场景分解**：
   - 通用文件上传保留给文档抽取（Word/PDF/PPT）。
   - 针对个人主页、海报等特定场景，在输入卡片上方动态展示轻量化的素材胶囊（如「＋ 上传头像」「＋ 上传微信二维码」）。
   - 前端限制单图 2MB 并支持单独删除；后端校验格式并以独立无序 UUID 托管，将稳定绝对地址安全注入模型上下文。
3. **“所见即所得”案例与行为分层**：
   - 案例展示区卡片采用真实 HTML（sandboxed iframe 缩放）+ 微光骨架（shimmer）加载过渡，真实呈现高级排版。
   - **主体点击行为**直接满足本能预期：“点击卡片任意区域，在新标签页打开预览全页”。
   - **「做同款」次级动作**轻量浮置于卡片右上角，点击精准聚焦输入框并高亮对应场景。

## 三、 双层链接架构：节点链接 vs 固定发布链接

在生成树（会话=树、Node=Page）架构下，单次生成与多轮修改都会产生新的 `page_id`：

1. **节点链接（`/p/{conversation_id}/{page_id}`）**：
   - 面向工作区、版本对比与内部临时调试，每次续写或更换模型产生新链接。
2. **固定发布链接（`/u/{slug}`）**：
   - 面向正式分发（印在纸质简历、挂在小红书简介、转发微信朋友圈）。
   - **一个会话永久对应一个稳定 Slug**。用户对网页进行二次迭代或切换模型后，点击“更新公开链接”只会改变其指向的当前版本，外部访问的 URL 始终不变。

## 四、 PLG 传播闭环：Shadow DOM 挂载浮标与海报生成

让每个公网访问的生成页都成为裂变入口：

1. **Shadow DOM 隔离的「做同款」浮标**：
   - 生成页通常包含不可控的第三方 CSS、重置样式甚至全屏动画，如果直接向 `<body>` 插入 HTML 挂件，极易被破坏或遮挡。
   - 方案：采用 `attachShadow({ mode: 'closed' })` 配合 `:host { all: initial }` 将浮标挂载到独立样式作用域中。
   - 浮标点击自动携带 `utm_source=made_with&scene={scene_key}&ref={slug}` 跳转回主站，形成自传播归因。
   - 打印样式声明 `@media print { display: none !important }`，保证简历或报告导出 PDF 时版面纯净。
2. **服务端确定性生成分享图与海报**：
   - 微信生态依赖 Open Graph 与朋友圈图片分享。不要依赖无头浏览器现场截屏（耗时长、容易超时或字体丢失）。
   - 发布时由服务端（Pillow）合成两套图片：
     - **横版分享卡（1200×630）**：提供给微信消息卡片（`og:image`）。
     - **竖版朋友圈长图海报（1080×1620）**：渐变背景 + 分行大标题 + 白底二维码卡片。
   - 移动端点击「发朋友圈」直接呼出海报浮层，引导用户长按保存图片。

## 五、 安全、隐私与数据纯净度

1. **案例库隐私防泄露**：
   - 运营人员在后台将优秀生成页标记为公开案例时，API **严禁回吐用户的原始 Prompt 与未清洗文本**（因用户常在输入中留下真实手机号与邮箱）。
   - 公开案例的 `remix_prompt` 应使用中立的场景模板，杜绝敏感信息外泄。
2. **外部访问计数的防刷防噪**：
   - 创作者本人预览自己的页面不计入“外部访问”（需通过登录态与签名匿名 Cookie 共同识别）。
   - 微信预览爬虫（如 `mpcrawler`）、各平台爬虫 UA 必须前置识别过滤，避免链接刚发出去卡片抓取就把访问量虚高刷起。
3. **CSP 沙箱沙盒权限边界**：
   - 放行内联样式/脚本的同时，沙箱 CSP 必须包含 `allow-modals`（`sandbox allow-scripts allow-modals allow-popups allow-popups-to-escape-sandbox`），否则调用 `window.print()` 会被浏览器静默阻断，导致“导出 PDF”功能假死。

## 六、 场景度量漏斗

在运营后台监控场景的端到端闭环漏斗，不看虚高的 DAU，看各环节转化率：

$$\text{落地访问 (Landing)} \longrightarrow \text{点击生成 (Click)} \longrightarrow \text{成功任务 (Success)} \longrightarrow \text{发布固定链接 (Publish)} \longrightarrow \text{外部真实访问 (Views)}$$

通过对比不同场景的发布率与外部传播比，判断当前产品在哪个垂直领域的 PMF（Product-Market Fit）更强，进而集中资源做内容投放与深耕。
