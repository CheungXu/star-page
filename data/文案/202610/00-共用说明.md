# 星页推广文案共用说明

只给写稿的人看。不要把这份说明原文贴进小红书正文。

## 产品，只许写这些

星页是网页工具。用户打开浏览器，把旧简历或一段经历丢进去，就能生成一份能在手机上打开的网页。

可以说的：

- 不用装软件，不用写代码，不用自己买服务器。
- 做好就是一条公网链接，微信里能点开。
- 同一次可以让多个国内模型各做一版，并排挑。
- 简历场景会按简历来做：经历清楚、联系方式可以打码、需要纸质版时能打印。

不许说的：

- 不许说星页能做 3D 小岛、游戏、可对话终端。那是别人用编程工具折腾出来的，不是星页。
- 不许教人装 Codex、Cursor、Node、Git。星页的卖点就是不用走那条路。
- 不许编造具体价格、注册送多少积分、虚假用户数、虚假点赞收藏。
- 不许做成假的小红书界面截图，不许在图上写假的点赞数。
- 网址如果要出现，只用 https://stars-page.com 。不要编活动码。

## 文案气质

像一个真人今晚发的笔记，不是品牌稿。

- 有具体的人：城市、岗位、一件刚发生的事。
- 句子短，可以有口语、可以有一点不工整。
- 少用「不仅、赋能、闭环、打造、助力、总之、首先其次」。
- 标题要像小红书会停下来的那种：有时间、有身份、有结果。一篇准备 5 个标题，正文用最像人话的那一个当主标题。
- 正文 280 到 520 字。结尾让人评论，不要硬广三段论。

## 图

封面竖图，接近 3:4，给小红书首图。图里尽量不要让模型写中文；中文很容易写错。字放在文案文档里。

生图二选一，密钥从 `config/llm.env` 读取，禁止把密钥写进文案、日志或图片文件名。

阿里云，Bearer 用 `LLM_API_KEY`：

```bash
curl --location 'https://llm-6dcc5zo2qmpwlv5g.cn-beijing.maas.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation' \
  --header 'Content-Type: application/json' \
  --header "Authorization: Bearer $LLM_API_KEY" \
  --data @payload.json
```

请求体模型名为 `qwen-image-3.0`，结构见用户给的示例。`prompt_extend` 可开。

字节，Bearer 用 `ARK_API_KEY`：

```bash
curl -X POST https://ark.cn-beijing.volces.com/api/v3/images/generations \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ARK_API_KEY" \
  -d @payload.json
```

模型 `doubao-seedream-5-0-pro-260628`。封面不要水印，`watermark` 设为 false。尺寸用竖图。

生成后必须用读图工具看实际画面。不合格就改提示词或换另一家接口，直到能当封面发出去。不合格包括：文字乱码、塑料皮肤、多余手指、构图不像手机封面、和这篇人设无关。

每个文件夹最终至少留一张通过的 `封面.png`。失败的试稿可以留在 `试稿/`，不要拿失败图当封面。

## 真实界面截图

AI 封面里的手机屏幕都是假界面，不能拿来说「这就是星页」。封面后面必须跟真实截图，读者才信。

拼好的 3:4 配图在 `00-界面截图/小红书配图/`：

- `图1b-粘贴经历.png`：首页选了「网页简历」，输入框里贴着一段经历。
- `图2-首页与简历成品.png`：左边是手机打开的首页，右边是做好的简历网页。
- `图3-两个模型并排出稿.png`：同一份经历，通义和豆包各出一版，并排在工作区里。
- `图4-手机上打开的成品.png`：博主主页、网页简历、活动邀请函三张手机成品。

每篇的配图顺序：

| 文案 | 封面后依次放 |
| --- | --- |
| 01 春招两分钟 | 图2、图3 |
| 02 设计师作品集 | 图4、图3 |
| 03 跳槽对比 | 图3、图2 |
| 04 编导作品 | 图4、图2 |
| 05 零基础对照 | 图1b、图3、图2 |

截图里的人物「林晓」「陈一然」都是虚构的示例。正文的人设是博主本人，不要说图里就是博主自己的简历。

实测一次生成要 2 到 5 分钟（通义 Flash 约 2 分钟，豆包 Turbo 约 4 分半）。可以写「几分钟」「等了一会儿」，不要写「秒出」「两分钟搞定」。
